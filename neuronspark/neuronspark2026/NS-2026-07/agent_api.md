
# Agent API

Submission root must contain `agent.py`. The judge imports it without network access and instantiates `Agent`. In the model-submission route, `agent.py` is the model loading and inference adapter: it may load offline assets from `model/`, `models/` or an equivalent submitted directory, keep recurrent state across calls, and emit one action per observation.

```python
class Agent:
    def reset(self, task_info: dict) -> None:
        ...

    def act(self, observation: dict) -> dict:
        ...
```

For GPU-efficient policies, `Agent` may additionally implement the optional batched interface:

```python
class Agent:
    def reset_batch(self, task_infos: list[dict]) -> None:
        ...

    def act_batch(self, observations: list[dict]) -> list[dict]:
        ...
```

When both optional methods exist, the judge may evaluate many rollouts from different tasks in one batched call, up to the official `max_batch_rollouts` setting. Each `task_info` and observation includes `batch_index`, `batch_size`, `task_batch_index`, `variant_batch_index` and `rollout_id`. Submissions that only implement `reset/act` remain valid and are evaluated sequentially. The cross-task batch API is the intended path for policies that use a large CNN/RNN/Transformer model and need to amortize inference on the RTX 4090D 24GB node.

`reset` is called once per task rollout. `task_info` contains public task geometry, object nominal properties, object family, environment context, task-combo description, target pose, tool goal and resource constraints. It does not contain private physics rollouts, hidden capability-tier labels, hard-slice labels, hidden scores or optimal actions.

`act` is called every control step. In r08 the default observation is generated by the MuJoCo dev simulator and includes low-dimensional state, estimated pose, velocity, per-finger tactile normal/shear/vibration/contact values, short tactile history, a 7x4 tactile heatmap, a compact `tactile_image_7x8x8`, contact summary, compact scene context, stage context, `vision_grid_16x16` top-down spatial tokens, sensor status, lightweight render/proxy features and warning flags. It must return one action matching `action_schema.json`.

Model weights, tokenizers, configs, lookup tables or helper files may be included inside the submitted zip, but runtime download, external API calls and network access are not allowed. The target model-submission resource boundary is an 8192MB zip, 16384MB extracted tree, 8000 files, 8192MB single file, and 12288MB total model files. Rules and optimization-only agents remain valid submissions, but high hidden scores are expected to require model-based temporal tactile perception, spatial-grid perception, contact recovery, multi-stage planning and cross-physics generalization. CNN/MLP/RNN/Transformer policies, BC/RL policies, world-model-style controllers and compact VLM-like encoders are all valid if they fit the resource limits. The optional batch API is intended for policies that benefit from the 4090D 24GB GPU while staying within per-call timeout. The public `train_tasks.jsonl` and `demonstrations/weak_train_rollouts.jsonl` files are intended for legal offline training. The official platform is expected to run hidden evaluation on the zxdmatrix GPU queue with aggregate feedback only.

## Official Runtime Contract

The official r08 model-submission runtime is the `ns202607-r08-torch-cu128` equivalent environment. If the platform publishes a Docker image, the expected image tag is `aigame-eval-ns202607-r08-torch-cu128:20260526` or a functionally equivalent image with a launch-time digest. The public ABI contract is Ubuntu 24.04.2 LTS, glibc 2.39, x86_64 Linux, CPython 3.12.3, 1 x RTX 4090 D 24564 MiB, NVIDIA driver 580.65.06, `torch==2.11.0+cu128`, PyTorch CUDA runtime 12.8, `mujoco==3.3.7`, `numpy==2.4.6`, `scipy==1.17.1` and `tqdm==4.67.3`.

See `GETTING_STARTED.md`, `RUNTIME_ENVIRONMENT.md` and `requirements-runtime.txt` for public simulator setup and the fixed runtime contract. The historical `aigame-eval-ns202607-mujoco:20260525` image is a CPU/MuJoCo smoke image and is not the r08 leaderboard model runtime. At launch, the platform problem page should publish either a registry pull command with digest or an offline runtime image archive for `aigame-eval-ns202607-r08-torch-cu128:20260526`. Only the listed packages are guaranteed; extra pure-Python dependencies should be bundled with the submission, and native binary dependencies outside the contract are unsupported unless they are compatible with CPython 3.12 and glibc 2.39 and import without installation.

Official scoring includes three hidden capability layers: base state-feedback control, tactile slip/contact recovery, and cross-task/cross-object/cross-physics generalization. The per-task capability label is withheld from `task_info` and from official feedback. Public valid/test scores are for local sanity only and must not determine leaderboard ranking; ranking must use hidden private procedural rollouts.

The reference resource contract is: agent startup timeout 30s, `reset` timeout 12s, `reset_batch` timeout 20s, single-rollout `act` timeout 2s, cross-task `act_batch` timeout 10s, hidden `max_batch_rollouts` 64, hidden horizon 128 control steps, and no network during evaluation. Platform-global wall time remains the outer hard limit.

## Gymnasium-style Dev Wrapper

The public package also includes `simulator/gymnasium_env.py`. It wraps the same public MuJoCo/proxy dev simulator as a Gymnasium-style environment for local training and debugging:

```python
from simulator.gymnasium_env import DexSimGymEnv

env = DexSimGymEnv(task_file="tasks/valid_tasks.jsonl", task_index=0)
obs, info = env.reset(seed=0)
obs, reward, terminated, truncated, info = env.step(env.sample_action())
```

`gymnasium` itself is optional. Without it, the wrapper still exposes `reset`, `step` and `sample_action`. With `observation_mode="compact"` it returns low-dimensional state and a 7x4 tactile heatmap suitable for small models. This wrapper is not the official submission API; official scoring still loads `agent.py`.

## Headless Replay

The public package includes a lightweight headless replay renderer. It does not include pre-rendered official videos; participants may generate local public-task replays themselves:

```bash
python -m pip install -r requirements-mujoco.txt
python tools/render_replay.py example_submission --tasks tasks/valid_tasks.jsonl --index 0 --output-dir replay_debug
```

It writes `replay_summary.json` and `replay_frames.zip`; if `ffmpeg` is available, it also writes `replay.mp4`. This is a public proxy visualization tool for debugging tactile-control failures.

Official hidden replay artifacts, when enabled, are limited to at most one bounded redacted replay generated from a non-scoring hidden-diagnostic task. The diagnostic task follows the same task-grammar family as hidden scoring tasks but is not part of official score aggregation. Official artifacts do not expose scored private rollout ids, hard-slice labels, hidden capability labels, private physics parameters or optimal actions, and replay artifact generation failure does not affect the score. The official platform keeps diagnostic artifacts short-lived; expected artifact types are redacted JSON and bounded frame ZIP files, while MP4 video is not guaranteed and is not a long-term archive.

Large submitted zip/model packages are stored through the `zxdmatrix-submission-blobs` path for evaluation dispatch, hash traceability, award review and writeup verification. The target retention for the original submitted package is 21 days when storage is healthy; diagnostic artifacts are short-lived debugging aids. Participants should keep their own final package, model manifest, checkpoint hashes, exported package sha256 and writeup evidence.
